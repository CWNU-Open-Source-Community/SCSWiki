# 国际大学生程序设计竞赛（ICPC）

三人团队协作解决算法问题，沿区域赛等赛事体系逐级参与挑战。

<EventDetails />

## 比赛简介

ICPC 是面向大学生的国际程序设计竞赛，区域赛事与全球总决赛构成其主要赛事体系。经典比赛形式是三名队员共用一台计算机，在限定时间内解决一组算法题。

除了找到算法，队伍还需要安排读题、推导、编码和验算。经典计分首先比较通过题数，再按规则比较用时；能够识别值得投入的题目、及时切换思路，也是训练的一部分。

## 适合谁参与

适合喜欢算法、愿意长期组队训练的同学。入门时不必一次掌握全部算法，但应能独立编写并调试完整程序，再逐步建立互补的知识分工。参赛年限、学籍和区域赛资格须按 ICPC 与赛站规则核对。

## 主要内容与参与方式

| 环节或方向 | 重点了解                                                                         |
| ---------- | -------------------------------------------------------------------------------- |
| 个人基础   | 复杂度分析、常用数据结构、搜索、动态规划与图论等逐步积累。                       |
| 团队协作   | 分配题目、共享推导结果、轮换使用设备，并交叉检查解法。                           |
| 赛站与晋级 | 不同地区、赛站和阶段有各自的报名及晋级安排，不能把一次网络练习等同于正式区域赛。 |

## 如何准备

以下是本站的学习建议，不是主办方附加的参赛条件。

1. 先做难度适中的往届题，尝试在看题解前写出自己的推导。
2. 组织固定队友，明确谁先读哪些题、何时换机、如何报告卡点。
3. 按目标赛制模拟，记录错误提交、排队等机器和长时间停滞的原因。
4. 赛后补题并核验常用代码，每个成员都要理解自己负责的模块。

## 常见问题

### 会做题就一定适合组队吗？

还需要练习解释思路与共同决策。队员之间能否明确说明算法成立的条件，会直接影响协作效率。

### 所有 ICPC 活动都使用同样规则吗？

不能一概而论。网络选拔、区域赛、邀请赛和总决赛的资格、设备与流程，应分别阅读说明。

## 参与总结

ICPC 的学习重点是算法深度与团队配合。建议保留模拟赛记录，观察“会做但没完成”的题为什么丢失机会，再有针对性地调整分工。

## 名称与收录范围

ICPC 官方英文全称为 International Collegiate Programming Contest。其赛事体系包括地区及更高层级赛事，不能用世界总决赛日程代表所有区域赛。历史资料中的 ACM-ICPC 可用于检索，不作为当前名称。
